# PhoneDrop — полностью бесплатная P2P-версия для Render

Передача файлов между компьютером и телефоном даже в **разных сетях**: Wi-Fi ↔ мобильный интернет, домашний ↔ рабочий Wi-Fi. Без Vercel, Яндекс Облака, регистраций и облачного хранения файлов.

- Коды комнат: **10 символов**, латиница/цифры без `O`, `0`, `I`, `1`.
- Подключение по **QR-коду**, ссылке или вводу кода.
- Фото, ZIP, SQL, видео и любые файлы — до **500 МБ напрямую через WebRTC**.
- При недоступном P2P — **резервная потоковая передача через Render WebSocket до 200 МБ**.
- Данные **не записываются на сервер**, передачи возможны только когда **оба браузера открыты одновременно**. При получении файла браузер предлагает его скачать.
- Бесплатный Render Web Service (план **Free**): один Node.js процесс, HTTPS, WebSocket, никаких дисков и БД.

## Схема

```text
Компьютер <-- WebSocket (сигнализация) --> Render Free <-- WebSocket --> телефон
    \________________ WebRTC P2P (данные напрямую) _____________/

Если прямой WebRTC не работает:
Компьютер <-- WebSocket (файл) --> Render Free <-- WebSocket (файл) --> телефон
                 (без записи в файлы или БД)
```

## Как развернуть на Render бесплатно

1. Зарегистрируйся в [render.com](https://render.com), желательно **без добавления банковской карты**. Если карту уже добавили — выстави ограничения расходов: Render может брать плату за превышение включённого трафика, даже при бесплатном веб-сервисе.
2. Создай **приватный репозиторий GitHub** и загрузи в корень содержимое этого архива (не сам ZIP). `.env` и секретов здесь нет. Для удобства можно использовать GitHub Desktop.
3. В панели Render выбери **New → Web Service → GitHub** и подключи репозиторий. Выбери проект `phonedrop-p2p`.
4. Выбери **Free** план; Runtime `Node`; Build Command: `npm install --omit=dev`; Start Command: `npm start`. Можно также выбрать **New → Blueprint** для использования файла `render.yaml` из репозитория.
5. Дождись статуса **Live**, затем открой адрес вида `https://phonedrop-p2p.onrender.com`. Настраивать переменные и базу данных не нужно.
6. Открой ссылку на компьютере, перейди на вкладку «Подключиться» → «QR-код», отсканируй телефоном (можно отключить Wi-Fi и оставить мобильную сеть). Когда появится «Второе устройство подключено», выбери ZIP или SQL.

## Бесплатные лимиты Render (актуальные на октябрь 2026; проверяй их в панели)

- **750 бесплатных instance-hours** в месяц на workspace.
- **5 ГБ исходящего трафика** в месяц для Hobby workspace, по сведениям [Render](https://render.com/docs/outbound-bandwidth). Для P2P файлы не проходят через Render. Передача через резервный режим расходует исходящий трафик.
- Бесплатная служба **засыпает через 15 минут без входящих запросов/WebSocket-сообщений**, первое открытие после сна может занимать ~1 минуту. Клиент переподключается автоматически.
- Без карты при превышении лимита исходящего трафика Render может приостановить бесплатные сервисы до начала следующего месяца. **С добавленной картой** возможны списания за превышения.
- Render может перезапускать бесплатный сервис. Текущие комнаты/передачи в этом случае разорвутся и нужно будет переподключиться.

## Особенности

- Прямое P2P использует STUN. **Без TURN** WebRTC может не пройти через симметричный NAT или некоторые мобильные сети. Тогда `Автоматически` через 12 секунд переключает отправку в WebSocket-режим (до 200 МБ на файл).
- При слишком большом файле, который не помещается в WebSocket-лимит, требуется успешное P2P. Передача любых файлов >200 МБ **между разными сетями не гарантирована**.
- Передача через сервер не является end-to-end шифрованной на прикладном уровне: используется HTTPS/WSS; файлы идут через сервер в оперативной памяти без записи на диск. WebRTC DataChannel шифруется DTLS.
- Два устройства на одну комнату. Пользователь с кодом может присоединиться как второе устройство, поэтому код не стоит публиковать.
- В мобильных браузерах получение файлов около 200–500 МБ может быть ограничено доступной оперативной памятью. Скачай полученный файл до закрытия страницы.
- Приложение не умеет пересылать файл на выключенное устройство, поскольку не использует постоянное хранилище.
- Если подключение Render из России недоступно у конкретного провайдера, этот вариант без VPN также не сработает.

## Локальный запуск и тесты

Нужен Node.js 20+:

```bash
npm install
npm test
npm start
```

Открой http://localhost:10000; чтобы протестировать два браузера на одном компьютере, открой один и тот же URL с одинаковым кодом в двух разных окнах/профилях. Реальный тест двух разных сетей делай только с публичным HTTPS URL на Render.

### Почему здесь не используется Яндекс Cloud или Vercel

Нужен строго бесплатный тариф без хранения файлов. Render Free принимает WebSocket, что позволяет сделать и сигнализацию для P2P, и временный relay в одном сервисе. Из-за бесплатного лимита трафика relay ограничен **200 МБ на файл**, но весь исходящий лимит рабочего пространства может исчерпаться и раньше.

Исходники: `server.js`, `public/app.js`, `public/index.html`, `public/styles.css`, `render.yaml`. Нет токенов, паролей, баз данных, облачных ключей. Полная доступность между любыми сетями без платного TURN не гарантируется.


## Телефон ↔ телефон

1. Откройте PhoneDrop на первом телефоне и нажмите «Поделиться комнатой», чтобы отправить ссылку второму (или покажите QR-код).
2. Откройте ссылку на втором телефоне; телефоны автоматически окажутся в одной комнате. Также можно ввести десятисимвольный код.
3. На любом телефоне выберите файл или нажмите «Снять фото». На другом нажмите «Скачать» либо «Поделиться / Сохранить» (если браузер разрешает передачу файлов через системное меню).
4. Не блокируйте экраны и не сворачивайте вкладки во время передачи. При невозможности P2P включается WebSocket-резерв; он ограничен 200 МБ, прямой P2P — 500 МБ.

Функция системного меню зависит от поддержки Web Share API в браузере; обычное скачивание доступно как запасной вариант.


## Дизайн 5.0 — мобильные экраны и графические ассеты

- Дизайн сделан по выбранному премиальному тёмному референсу: глубокий графит, фиолетовый свет, космический фон и фотографии смартфонов.
- `public/assets/`: `cosmos-bg.webp`, `phones-orbit.webp`, `orbits.webp`, `room-art.webp`, `brand-mark.webp`. Все графические ассеты хранятся прямо в проекте и обслуживаются самим Node.js сервером; внешние CDN не используются.
- Три вкладки: **Комната**, **Файлы**, **Подключиться**. На мобильных документ не прокручивается; прокрутка появляется внутри конкретного экрана только при недостатке места или длинной истории файлов.
- Отправка открывается снизу: фото/видео, файлы, камера, папка (выбор папок поддерживается не всеми браузерами). После выбора файлов открывается предпросмотр выбранного и кнопка подтверждения отправки.
- Вкладка «Файлы» показывает отдельно отправленные и полученные файлы, вместе с прогрессом и действиями сохранения. История — только текущая открытая сессия; после перезагрузки она очищается.
- QR генерируется сервером для **реального 10-символьного кода**, а не зафиксированного числа из графического референса.
- Статический комплект WebP имеет небольшой вес и не зависит от платных сервисов.
